## Decisions the tick left open, and how I read them

- The degraded summary carries the CAUSE ("forge unreadable"), not the state
  word prefixed. The tick's examples ("degraded: forge unreadable") are the
  composed headline of epic rule 3, which the wave-3 renderer builds from
  `state` + summary ("● degraded: …" in u5n); a summary that repeated the
  word would render "degraded: degraded: forge unreadable". The tick's
  stopped rule confirms the reading: its summary is liveness.reason, plainly
  the why.
- "No later activity line for that attempt": any feed line for the same
  (tick, attempt) after the nudge answers it, EXCEPT the watcher's own quiet
  statements (another stuck_nudged, stuck_stopped, stall_warned,
  wall_clock_fired) — the run writes no positive activity line for an
  in-flight attempt, and its problem-watcher restating the nudge's own cause
  is not the worker doing something. A `waiting` prompt-nudge (the runner
  ended a turn) or a wip_nudged line (the worker produced a large change)
  answers it. Position in the append-only feed is the clock, the package's
  own rule.
- The stopped rule is implemented literally: NOT stopped only when the
  lifecycle phase is `done` or `cancelled`. A completed run whose merge
  phase still stands (phase `merge`, process gone) therefore reads STOPPED,
  with its liveness reason as the summary and the merge wait in needs-you.
  The tick's parenthetical ("a dead run or a failed run") and the wave-1
  `status_model_completed_awaiting_merge` golden (alive=false, phase=merge,
  verdict healthy) point the other way — see the finding below. Nothing in
  the tick's six test cases pins either answer for phase merge.
- The decisions line follows the tick literally: metered at the existing sum
  whenever any decision exists, omitted only when none do. A run whose
  decisions all carry no usage would state metered $0.00 over 0 attempts —
  pathological (a decision records the exchange's usage), and the schema's
  metered arm admits it.
